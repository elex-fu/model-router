## 实现范围

- **共享额度**：同一 Redis 状态引擎用于日配额和 SaaS 租户/项目/API key 的 RPM、TPM、并发准入。
  准入、额度变更和写回日志由 Lua 原子更新；进程内只保留请求路由信息，不保存额度余额。
- **缓存优先、数据库异步**：命中直接读 Redis；缺失读取数据库并回填，版本检查防止旧回源覆盖新值。
  每 100 ms、最多 100 个事件进行一次后台写回，幂等版本和数据库 generation 阻止重复或过期写入。
  多网关共用 PostgreSQL；现有自托管实例复用同一引擎并使用 SQLite 持久化适配器。
- **故障策略**：数据库健康租期 2 秒、待写回阈值 10,000；故障或积压停止新准入，已接收请求仍可更新 Redis 并结算。
  Redis 进程重启后建立新 generation，从数据库恢复已确认状态，避免旧 AOF/RDB 回退已落库额度。
  未落库更新仍存在用户接受的短暂丢失窗口。Redis 使用 AOF `everysec`、`noeviction`。
- **鉴权内存缓存**：SaaS 仅缓存成功鉴权，最多 4,096 条、TTL 5 秒且不超过 key 到期时间，合并并发查询；
  准入阶段仍核对授权版本。失败和拒绝结果不进入缓存。
- **普通日志异步**：代理不再等待三个日志批次提交；日志由有界 worker 队列处理，失败/满队列记录丢弃数。
  额度恢复使用独立业务状态及 usage journal。自托管旧日志中的额度、时区和响应归属已迁移至 `control.sqlite`。

金额账本、累计 key 预算、billing-group 消费预算、金融结算及持久化派发凭证继续使用 PostgreSQL 事务。
本轮没有宣称所有 SaaS 数据库操作都移出了请求路径。迁移 138 和更新后的运行角色授权已加入；
多实例升级须统一启用 Redis，详见 [部署说明](../../../../deploy/README.md#managed-saas-startup-contract)。

## 服务器真实 Kimi 前后比较

同一 1 CPU/1817 MiB 服务器、Node 22.22.0；模型 `kimi-k2.6`，同一短提示，最多 32 token，
关闭 thinking，使用 SSE。2 次预热和 40 次正式请求全部成功；各组 10 个正式样本。
本轮按直连、网关并发 1、2、5 顺序执行，完成期间服务器负载约 0.1。

| 路径 | 完成 p50：优化前 → 后 | 本轮完成 p95 | 观测吞吐：前 → 后 |
| --- | ---: | ---: | ---: |
| 直连上游，并发 1 | 642.37 → 575.96 ms | 1099.72 ms | 1.50 → 1.58 req/s |
| 网关，并发 1 | 1376.17 → 580.38 ms | 646.98 ms | 0.73 → 1.69 req/s |
| 网关，并发 2 | 1374.14 → 607.52 ms | 748.03 ms | 1.47 → 3.11 req/s |
| 网关，并发 5 | 1372.32 → 633.56 ms | 735.17 ms | 3.50 → 7.06 req/s |

串行网关完成 p50 下降 **57.83%**，并发 5 的短批吞吐约为原来的 **2.02 倍**。
本轮网关串行 p50 与直连相近，符合移除原有约 756 ms 日志批次等待的预期。
两次测量发生在不同时间，且直连与网关为顺序采样；真实供应商与网络波动仍在，
不能把 p50 的差值当作严格的纯网关开销。每组 10 样本也不代表持续容量或生产 SLO。

并发 5 时路由进程 CPU 为 **8.47%**、RSS 峰值 **165.6 MiB**；旧基线对应为 2.10%、137 MiB。
该 CPU 口径沿用旧基线，不包含独立 Redis 进程。最终 Redis 数据使用约 **1.25 MiB**，服务内存约 **7.2 MiB**。

## 优化后代理与 Kimi 直连：五轮交替实测

北京时间 2026-10-24 01:15:44–01:16:59，在同一服务器上追加运行 5 轮，每轮直连和代理各 10 次，
共 **100 次正式请求，100 次成功**。另有各路径 2 次预热，均成功，不计入统计。
每轮包含 5 对“直连→代理”和 5 对“代理→直连”，并发为 1，轮间间隔 3 秒；没有重试或剔除慢样本。
代理走服务器本机 `127.0.0.1:15005`，直连走相同的唯一启用上游，发布清单摘要与前述版本相同。

两条路径均使用 `kimi-k2.6`、同一提示 `Reply with exactly OK.`、SSE、`max_tokens=32`、关闭 thinking。
所有正式请求都返回 `OK` 和流终止事件；上游报告的输出均为 11 token，缓存读取均为 23 input token。
因此这组数据描述已预热、短提示重复调用，不能外推为未命中提示缓存或长输出表现。
